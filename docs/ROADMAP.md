# Scientific Roadmap

> **Status:** active research roadmap  
> **Current baseline:** S0–S3 validated at commit `e52fbaf`  
> **Next major milestone:** S4 — GRHD in Kerr–Schild spacetime

This document defines the scientific development plan for **blackholesim**. The project follows two parallel tracks:

1. increase the physical realism of the renderer and radiative-transfer pipeline;
2. build and validate a standalone GRHD/GRMHD solver that exchanges data with the renderer through HDF5 snapshots.

The two systems remain deliberately decoupled.

---

## 1. Five realism tracks

| Track | Goal | Dependency | Status |
|---|---|---|---|
| 1 | Time variability and interstellar scattering | none | planned |
| 2 | Electron temperature prescription (`R_high/R_low`) | `PlasmaState` | planned |
| 3 | Physical synchrotron emission at 230 GHz | Track 2 | planned |
| 4 | Full Stokes `I,Q,U,V` transfer + Faraday effects | Track 3 + physical magnetic field | planned |
| 5 | Self-consistent GRMHD solver | independent long-term track | in progress |

### Shared infrastructure

| Component | Role | Status |
|---|---|---|
| `PlasmaState` | Common plasma → renderer interface for CPU/CUDA | implemented |
| iharm-compatible HDF5 reader | Public/reference snapshots + solver output | planned |
| iharm-compatible HDF5 writer | GRMHD solver output | partial / staged |
| `ipole` comparison | Polarized-transfer validation | planned |
| GRMHD benchmark suite | Solver validation | in progress |

---

## 2. Recommended execution order

### Phase A — renderer realism without GRMHD

1. Time variability and interstellar scattering.
2. Electron-temperature prescription.
3. 230 GHz synchrotron, Stokes I only.

### Phase B — physical magnetic fields

4. Read public iharm-style HDF5 snapshots.
5. Add full polarized transfer and validate against `ipole` using the same physical snapshot.

### Phase C — self-consistent solver

6. Continue the staged GRHD → GRMHD program below.
7. Replace public snapshots with snapshots generated by blackholesim only after the solver passes independent validation.

The key design choice is to avoid blocking polarization work on the completion of the in-house GRMHD solver.

# GRHD / GRMHD solver program

## Architecture

```text
[ standalone grmhd/ solver ]
            │
            ▼
  iharm-compatible HDF5
            │
            ▼
[ renderer + radiative transfer ]
```

The solver does not depend on the renderer. The renderer only depends on the snapshot contract.

This allows:
- independent testing;
- comparison against established solvers;
- use of public GRMHD snapshots;
- renderer development before the in-house solver is complete.

---

## S0 — infrastructure and output ✅

Purpose:
- establish the standalone `grmhd/` area;
- define data structures;
- provide inspectable output early.

Principle: diagnostic/output infrastructure is part of the numerical method, not an afterthought.

---

## S1 — Kerr–Schild geometry and coordinates ✅

Implemented components include:
- spherical Kerr–Schild metric;
- inverse metric;
- determinant and `sqrt(-g)`;
- Christoffel symbols;
- MKS coordinate mapping;
- geometry validation against independent formulations.

### Validation lessons

The geometry work deliberately rejected several initially plausible but weak tests.

Examples:
- metric compatibility alone can become algebraically self-confirming if the same derivatives define both the metric derivative and connection;
- convergence must be measured where truncation error dominates floating-point noise;
- relative error must not be normalized by a reference quantity that vanishes.

The consolidated S1 suite includes cross-checks against the independent Boyer–Lindquist Hamiltonian ray tracer and verifies geodesic invariants.

### Pre-S4 hardening

`KerrSchild::christoffel()` now has an explicit failure channel. Metric inversion failure can no longer silently masquerade as `Γ = 0`.

Kerr parameters are explicitly restricted to

```text
M > 0
|a| <= M
```

with the extremal case `|a| = M` supported and naked-singularity parameters rejected.

---

## S2 — relativistic hydro primitive recovery ✅

Primitive convention:

```text
P = (rho, u, u_tilde^i)
```

where `u` is internal-energy density and `u_tilde^i` is the spatial velocity variable measured relative to the normal observer.

Conserved Valencia variables in flat space:

```text
D   = rho W
S_i = rho h W^2 v_i
tau = rho h W^2 - p - D
```

### Numerical design

- analytic primitive → conserved map;
- one-dimensional safeguarded root solve for conserved → primitive;
- explicit admissibility checks;
- no hidden physical repair inside S2;
- conditioning diagnostics for cold/high-Lorentz-factor states.

The suite samples **145,036 states** and includes long-double reference checks.

### Important conditioning limit

Internal energy can become information-theoretically unrecoverable when it is the tiny difference of much larger conservative quantities. The code reports this condition instead of pretending to recover precision that no longer exists in the stored state.

---

## S3 — finite-volume SRHD ✅

Current solver ingredients:

- finite-volume formulation;
- relativistic characteristic speeds with transverse velocity;
- HLLE;
- PLM reconstruction with minmod / MC limiters;
- SSPRK2;
- periodic and outflow boundaries;
- explicit floor policy;
- explicit primitive-recovery failure policy;
- transactional rollback;
- independent exact SRHD Riemann oracle;
- HDF5 snapshot path.

### Validation

The suite checks:
- physical flux identities;
- causality of relativistic signal speeds;
- HLLE consistency and supersonic limits;
- global discrete conservation;
- smooth-mode convergence;
- relativistic shock tubes;
- Lorentz covariance checks;
- HDF5 round trips;
- recovery-failure semantics;
- stage-2 rollback;
- diagnostic rollback;
- vacuum-domain rejection;
- exact-oracle symmetry;
- acoustic-wave convergence;
- numerical-guard activation counts.

### Exact Riemann oracle hardening

Two important failure modes were found during independent review:

1. **Vacuum formation** was not part of the oracle's domain. It is now detected explicitly and returned as `VacuumFormed` instead of producing a plausible but nonphysical root.
2. The shock branch originally used the unsigned magnitude of the mass flux in a relation where wave-family orientation matters. A symmetric two-shock collision exposed the error because symmetry requires `v* = 0` exactly.

This is an explicit example of why a tiny residual is not sufficient evidence that an oracle is physically correct.

## S4 — GRHD in Kerr–Schild spacetime ⏭️

Goal: evolve relativistic hydrodynamics on curved Kerr spacetime, still without magnetic fields.

Required changes:
- spatial metric `gamma_ij` in velocity norms and index operations;
- lapse and shift in fluxes;
- metric-derivative source terms;
- curved-space conservative formulation;
- geometry-aware CFL and recovery.

### Decisive tests

**Bondi/Michel accretion**
- exact stationary spherical accretion solution;
- highly sensitive to source-term or metric inconsistencies.

**Hydrodynamic Fishbone–Moncrief torus**
- equilibrium configuration;
- should remain stationary apart from truncation error.

S4 should not be considered complete merely because a Kerr flow evolves without crashing.

---

## S5 — magnetic GRMHD

Four distinct components:

1. add magnetic fields and Maxwell terms to the stress-energy tensor;
2. implement magnetized primitive recovery (Noble et al. 2006 class of methods);
3. add the induction equation and constrained transport;
4. validate with SRMHD shock tubes and curved-space tests.

The magnetized inversion is a different algorithm from the hydro-only S2 recovery.

### Non-negotiable invariant

```text
div B ≈ machine precision
```

for constrained-transport tests over long integrations.

---

## S6 — production floors, ceilings and boundaries

Introduce systematic policies for:
- density and internal-energy floors;
- magnetization ceilings;
- Lorentz-factor ceilings;
- radial outflow boundaries;
- polar-axis treatment;
- azimuthal periodicity.

All interventions must be instrumented. A simulation that only survives because large fractions of the domain are repeatedly repaired is not considered physically validated.

---

## S7 — magnetized torus, MRI and community comparison

Target:
- Fishbone–Moncrief torus;
- weak poloidal magnetic loop;
- MRI growth;
- long-term turbulent accretion.

Validation includes:
- linear MRI growth rate vs analytic prediction;
- accretion rate;
- horizon magnetic flux;
- time-series statistics;
- comparison with published multi-code benchmarks such as Porth et al. (2019).

### 2D first, 3D eventually required

Axisymmetric 2D is useful for development and many tests, but sustained MRI turbulence ultimately requires 3D. Cowling's anti-dynamo theorem prevents indefinite maintenance of axisymmetric magnetic turbulence.

# Radiative-transfer roadmap

## Electron temperature

Introduce a physically motivated electron-temperature prescription such as `R_high/R_low` rather than deriving electron temperature directly from the current procedural thermal model.

## 230 GHz synchrotron

Use published thermal synchrotron coefficients (e.g. Pandya et al. 2016) and work in physical frequency space.

Validation should isolate coefficient evaluation before integrating full images.

## Polarization

Target full Stokes transfer:

```text
I, Q, U, V
```

including emission, absorption, Faraday rotation and Faraday conversion.

Because strongly Faraday-rotating regimes can be stiff, a naive explicit RK4 transfer integrator is not considered sufficient by default. Semi-analytic segment propagators and comparison with established polarized-transfer codes are preferred.

## Cross-code validation

The intended high-value test is:

```text
same GRMHD snapshot
same observing frequency
same camera
       │
       ├── blackholesim
       └── ipole
```

and then compare Stokes images quantitatively rather than by eye.

# Validation philosophy

The main scientific risk is not a crash. It is a **plausible but wrong result**.

The project therefore follows these rules:

1. No major numerical component advances without a discriminating test.
2. Prefer analytic solutions when available.
3. Track invariants continuously.
4. Run convergence studies at multiple resolutions.
5. Ensure stationary solutions remain stationary.
6. Compare against published independent results.
7. Count floors, fallbacks and numerical guards.
8. Treat visually convincing output as illustration, never validation.
9. Actively search for tests that pass for the wrong reason.
10. Preserve failure information rather than silently repairing unsupported states.

# When snapshots become useful to the renderer

- **After S4:** curved-spacetime hydro snapshots provide density and velocity but no magnetic field.
- **After S5–S7:** magnetized snapshots can support physical synchrotron emission and polarization.

## Scope note

A minimal but scientifically defensible GRMHD code is a multi-thousand-line numerical project whose validation effort is at least as important as implementation. The roadmap intentionally treats the solver as a long-term research track rather than a shortcut to prettier renders.
